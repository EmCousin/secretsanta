# Android Hotwire Native experiment

This is a first prototype, not a release build. The debug APK opens a local preview at `http://localhost:8765/` through the Android device's loopback. Use `adb reverse tcp:8765 tcp:8765` with a development server on the host; debug-only network configuration permits cleartext for localhost. Invitations created in this preview use localhost and are not shareable with other devices. Release builds use the HTTPS site and do not allow cleartext. The app does not yet register app links or add a native share bridge. Until the matching web change is deployed, the published site does not load Turbo for Hotwire and a release build cannot be expected to work.

Builds require an Android SDK (API 35), Java 17, Gradle compatible with Android Gradle Plugin 8.13.2, and network access for build dependencies. Install and license those tools separately; no SDK, Gradle wrapper, keystore or signing credentials are included. From this directory, run `gradle :app:assembleDebug` in a properly configured environment. The application ID is provisional and must be chosen before any release or verified App Links setup.

On an Android 15 x86_64 emulator, the local preview launched, completed a two-person draw, and relaunched and drew again after the host connection was removed. This is not a test of the production HTTPS origin, real device networking, cross-device links, or native sharing. Before considering this usable, test on a real Android device: initial online launch, later offline launch and draws, explicit save/restore, language changes, browser-compatible fragment invitations, share/copy fallbacks, process restart, and external navigation. Do not log personal data or invitation URLs. The web and native WebView may have separate local storage. iOS needs a separate implementation and a Mac with Xcode.
